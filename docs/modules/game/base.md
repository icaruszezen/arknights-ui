# 游戏 · 基建

> 一艘船的剖面图。每个房间一种颜色，数字用工业风的伪等宽体。

> 本篇为观察归纳，数值为估计。

## 整体

- **剖面视角。** 基建是罗德岛本舰的侧剖图：若干层、若干房间，像一张建筑剖面图。玩家拖动查看，点击房间进入。
- **房间即入口。** 每个设施是剖面中的一个矩形房间，里面有 Q 版小人在工作。不需要另设菜单。
- **类型色。** 不同设施有固定的主题色，房间边框、图标底、详情面板的强调边都用它：

| 设施 | 类型色 |
| --- | --- |
| 制造站 | 黄 |
| 贸易站 | 蓝 |
| 发电站 | 绿 |
| 控制中枢、宿舍、会客室、加工站、办公室、训练室 | 中性或各自的次要色 |

- **Bender 字体的主场。** 基建大量使用 Bender 这款工业风的伪等宽体显示数字与英文标签，分析文章专门提到它强化了基建的科技硬核感。

## 设施详情：抽屉

- 点击房间后，详情以**抽屉**形式从右侧滑入，占据屏幕右侧一部分；左侧仍能看到房间内部。
- 抽屉顶部是设施名（中文 + 英文）与等级，用类型色标记。
- 内容区依次是：进驻干员（头像方格）、当前产出与进度条、效率加成。
- 抽屉应当可以直接关闭。早期版本关闭时有二次确认，被认为不符合抽屉这种轻量容器的常规逻辑。

## 干员加成标签的三次迭代

基建里每个干员在不同设施有不同的加成，如何在一张小头像上表达这一点，官方迭代了三版：

| 版本 | 做法 | 问题 |
| --- | --- | --- |
| 1 | 文字标签 | 小尺寸下难以辨认 |
| 2 | 统一图标 | 能看出“有加成”，但分不出强弱 |
| 3 | 差异化图标 + 圆环 | 图标区分类型，圆环表达效果优劣 |

这是一个很好的案例：**信息密度高时，从文字 → 图标 → 图标 + 第二维度编码**。

## 通知与批量操作

- 左上角的通知入口汇总所有可收取的产出、可交付的订单、疲劳的干员，一键处理。
- 贸易站支持按已有材料批量交付订单——减少重复点击是基建后续优化的主线。
- 访问好友基建后，返回应回到好友列表，而不是自己的基建。返回的目的地要符合用户的来路。

## 规范

| 项 | 值 | 可信度 |
| --- | --- | --- |
| 数字 / 英文标签 | `--ark-font-family-data` | 社区 |
| 房间 | 直角矩形，1–2px 类型色描边，内部为场景 | 估计 |
| 抽屉宽度 | 屏宽的 35–45% | 估计 |
| 抽屉底色 | 石墨半透明，左缘一条类型色强调边 | 估计 |
| 抽屉入场 | 自右向左平移，`--ark-motion-duration-base` | 估计 |
| 进度条 | 高 6–8px，直角，类型色 | 估计 |
| 干员头像格 | 正方形，右下角叠加成图标与圆环 | 估计 |
| 心情 / 疲劳 | 细条或环，低于阈值转红 | 估计 |
| 倒计时 | 数据体 `HH:MM:SS` | 估计 |

## 可借鉴的做法

1. **空间即导航。** 把功能放进一张剖面图里，位置本身就是记忆线索。
2. **类型色贯穿到底。** 从房间到抽屉到进度条，同一种颜色一路标下去，用户始终知道自己在哪个系统里。
3. **抽屉保留上下文。** 详情不占满屏，背后的房间仍然可见。
4. **小图标上的二维编码。** 图形表达“是什么”，圆环表达“有多强”。
5. **汇总入口。** 分散在各房间的待办集中到一个通知面板。
