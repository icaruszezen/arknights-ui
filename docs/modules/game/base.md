# 游戏 · 基建

> 一艘船的剖面图。每个房间一种颜色，数字用工业风的伪等宽体。

> 本篇原先是观察归纳。2026-10-07 对实机截图核对了总览里的房间卡片、类型色和进驻信息，改过的地方标「社区（实机截图）」。

## 整体

- **两种视图。** 一种是罗德岛本舰的侧剖图：若干层、若干房间，像一张建筑剖面图，里面有 Q 版小人在工作。另一种是总览：同样的位置关系，但每个房间画成一张深色的卡片。两种都可以拖动查看，点击房间进入。
- **房间即入口。** 每个设施就是一个可点的房间，不需要另设菜单。
- **类型色。** 不同设施有固定的主题色。总览的卡片上，它是**左侧一条粗边**、等级的小竖条、状态文字和进度条的颜色：

| 设施 | 类型色 | Token |
| --- | --- | --- |
| 制造站 | 黄 `#ffcc00` | `--ark-color-facility-factory` |
| 贸易站 | 蓝 `#33ccff` | `--ark-color-facility-trading` |
| 发电站 | 黄绿 `#ccff66` | `--ark-color-facility-power` |
| 控制中枢、宿舍、会客室、加工站、办公室、训练室 | 中性 | — |

### 总览里的房间卡片

- 深色的实底，左侧一条类型色的粗边（720p 下 12px 宽）。卡片有很小的圆角，左边那条是单独的一块，像票根。
- 标题是白色粗体的设施名，后面跟几颗类型色的**小竖条**——几级就是几颗，不写数字。
- 标题下一行类型色的小字写设施现在在做什么：“生产中”“获取中”“发电中”。
- 底边一排进度格，右下角是进驻人数（`3/3`，当前值是类型色）。
- 有待处理的事时（订单可交付、产物可收取），整张卡片加一圈类型色的描边和光晕，右上角骑着一个圆形的图标气泡。平时只有左边那条粗边。

- **Bender 字体的主场。** 基建大量使用 Bender 这款工业风的伪等宽体显示数字与英文标签，分析文章专门提到它强化了基建的科技硬核感。

## 设施详情：抽屉

- 点击房间后，详情以**抽屉**形式从右侧滑入，占据屏幕右侧一部分；左侧仍能看到房间内部。
- 抽屉是纸白的，没有类型色的边。顶部一行标题（“当前房间入住信息”）和一个“清空”按钮。
- 进驻信息一人一行，每行是一块石墨色的条：左边头像，右边名字，下面两条——
  - **心情**是一条带字的粗条：左端白色的填充上写“心情”，没填到的部分是灰的，右端写 `15/24`（当前值大一号）。
  - 再下面一条灰底白字写状态和剩余时间（`工作中 16:16:16`）。
- 头像下缘另有一条很细的心情线，左下角一个黄色的笑脸。
- 抽屉应当可以直接关闭。早期版本关闭时有二次确认，被认为不符合抽屉这种轻量容器的常规逻辑。

## 干员加成标签的三次迭代

基建里每个干员在不同设施有不同的加成，如何在一张小头像上表达这一点，官方迭代了三版：

| 版本 | 做法 | 问题 |
| --- | --- | --- |
| 1 | 文字标签 | 小尺寸下难以辨认 |
| 2 | 统一图标 | 能看出“有加成”，但分不出强弱 |
| 3 | 差异化图标 + 圆环 | 图标区分类型，圆环表达效果优劣 |

这是一个很好的案例：**信息密度高时，从文字 → 图标 → 图标 + 第二维度编码**。

## 通知与批量操作

- 左上角的通知入口汇总所有可收取的产出、可交付的订单、疲劳的干员，一键处理。
- 贸易站支持按已有材料批量交付订单——减少重复点击是基建后续优化的主线。
- 访问好友基建后，返回应回到好友列表，而不是自己的基建。返回的目的地要符合用户的来路。

## 可借鉴的做法

1. **空间即导航。** 把功能放进一张剖面图里，位置本身就是记忆线索。
2. **类型色贯穿到底。** 从房间到抽屉到进度条，同一种颜色一路标下去，用户始终知道自己在哪个系统里。
3. **抽屉保留上下文。** 详情不占满屏，背后的房间仍然可见。
4. **小图标上的二维编码。** 图形表达“是什么”，圆环表达“有多强”。
5. **汇总入口。** 分散在各房间的待办集中到一个通知面板。
