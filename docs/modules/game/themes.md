# 游戏 · 界面主题

> 同一副骨架，十几种皮肤。界面主题证明了这套设计的结构与表皮是可以分开的。

## 什么是界面主题

自 2023 年 10 月 1 日起，游戏提供“界面主题更换”功能。PRTS Wiki 对它的描述是：在不变动功能的情况下，对 PRTS 界面进行了重新设计。

主题改变的元素：

- 主界面右侧菜单按钮
- 主界面左下侧菜单按钮
- 左侧标志图案
- 部分主题还会改变红点提醒与助理语音框的样式

不改变的：面板的位置、大小、层级、功能入口的顺序。

部分主题带有动态效果，部分支持时间轮替（根据服务器时间自动切换日夜样式）。

## 从主题系统能学到什么

### 1. 哪些东西是“骨架”

所有主题共有、从不改变的部分，就是这套设计真正的结构：

- 左助理、右面板组的左右分工；
- 右面板组的错位拼合与大小关系（作战最大）；
- 每块面板“中文大字 + 英文小字”的信息结构；
- 顶部资源条、左上角功能图标的位置。

### 2. 哪些东西是“表皮”

可以随主题更换的部分：

- 面板的底色、材质与边缘形状（直角可以变成纸张、木牌、金属铭牌、舞台幕布……）；
- 标题字体（黑体 / 宋体可以换成手写体、装饰体）；
- 强调色；
- 图标与标志图案；
- 红点、语音框等小部件的造型；
- 是否有动态效果。

### 3. 设计 token 应当怎样分层

主题系统对应到设计 token 上，就是“语义层”与“取值层”的分离：

| 层 | 例子 | 主题间是否变化 |
| --- | --- | --- |
| 结构 | 面板网格、间距、层级顺序、点击区 | 不变 |
| 语义 | `surface-primary`、`surface-secondary`、`signal`、`font-command` | 名称不变 |
| 取值 | `#fdfdfb`、`#424242`、`#18d1ff`、思源宋体 | 每个主题一套 |

本仓库的 [`tokens.json`](../../../tokens/tokens.json) 目前只有一套取值（接近默认的“日间”与官网风格）。如果要做多主题，建议在其上加一层语义别名，再为每个主题提供一组覆盖值。

### 4. 日 / 夜是最基本的一对

默认提供的“日间”与“夜间”是一组明暗主题。时间轮替主题进一步把明暗与真实时间绑定。对应到网页，就是 `prefers-color-scheme` 加一个手动切换。

### 5. 联动主题的边界

部分主题来自联动活动，会把合作方的视觉语言带进来，但仍然只改表皮。这给“品牌适配”划了一条线：可以换颜色、字体、材质，但不动信息结构。ak-ui 的设计文档里有类似的表述——去掉风格化样式后，产品应当仍然是使用者自己的产品。
